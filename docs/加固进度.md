## 新增或变更的配置、环境变量、协议

- 服务端：`CONFIG_SIGNING_KEY`（base64 的 32 字节 Ed25519 seed，空 = 不签名；`dev:all` 未设置时自动生成并在日志打印 `config_pubkey`）、`RATE_PUBLIC_PER_MIN_IP`（默认 120）。`NODE_ENV=production` 时使用开发默认票据密钥或少于 32 字符的 `ADMIN_TOKEN` 拒绝启动。`deploy/docker-compose.yml` 与 `deploy/.env.example` 已加 `CONFIG_SIGNING_KEY`。
- `GET /v1/config` 新字段 `config_sig`（base64，64 字节签名）。被签名字节：`"rterm-config-v1\n"` + 规范化 JSON（`{"adapters":…,"claude_catalog":…}`，键按 UTF-16 码元排序、紧凑、仅整数）。实现：`server/src/config-sign.ts`、`crates/rterm-core/src/config_sig.rs`，两端共用测试向量（`hardening.test.ts` 的 `VEC` 与 `config_sig.rs` 测试常量）。
- 客户端内置公钥常量：`crates/rterm-core/src/config_sig.rs` 的 `BUILTIN_PUBKEYS`（当前一把：`Na4pV+9TUsMFqdvHFitGAe9jqObG9m2b5/XL6aV39OI=`）。覆盖：`RTERM_CONFIG_PUBKEY`（debug 构建，或同时设 `RTERM_ALLOW_CONFIG_PUBKEY_OVERRIDE=1`）；`CoreOptions.config_pubkeys`（嵌入/测试）。
- 客户端：`RTERM_ALLOW_INSECURE_LOOPBACK=1`（发布构建下允许回环地址明文 http/ws；debug 构建默认允许）；终端内环境变量 `RTERM_HOOK_TOKEN`。
- 协议：`proto/rterm.proto` 的 `AppNotice.truncated = 8`；本机 IPC 消息增加 `token` 字段。
- API 变化（其他 crate 需注意）：`crypto::derive_pw_key`、`derive_pw_key_async` 返回 `Result<[u8; 32], CryptoError>`；`host::guard::Kdf` 返回 `Result`；`PasswordInput::derive` 返回 `Result`；`PasswordError` 新增 `TooFewClasses`、`Kdf`；`MIN_FIXED_LEN` 现为 10；`host::actions::AppSnapshot` 新增 `pending_truncated`；`CoreOptions` 新增 `config_pubkeys`；`InboxConfig` 新增 `max_files`。
- 服务端 `DEFAULT_ADAPTERS` 已对齐客户端内置规则（`claude-code` 的 `newline_in_paste` 为 `\n`，带 `attach_separate`）。
