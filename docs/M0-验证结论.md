# M0 验证结论

验证环境：Windows 10 Enterprise LTSC 2021（10.0.19044.7725，系统自带 ConPTY），Rust 1.99.1，Claude Code 2.1.322（原生 `claude.exe`，已登录），日期 2026-11-11。
原型和脚本在 `tools/spike-pty`（S1 原版示例）和 `tools/spike-s2`（脚本化的 PTY 驱动器 `spike-s2`、模拟 `rterm-cli hook` 的 `hookprobe`，场景脚本都在该目录的 `*.txt`）。
完整链路的端到端验证是 `crates/rterm-core/tests/host_claude_e2e.rs`（`--ignored`）。

**本机无法验证的内容**：Windows 11、macOS、Linux 上的一切行为（本机只有这一台 Win10）；需要真正调用模型才能观察的行为（见各表“未验证”）。Linux/macOS 的代码只做了 `cargo check --target`（类型检查）。

**一次意外**：S2 的第一轮试验里，我往输入框粘贴了含 CR 的多行文本，CR 被当成回车，“第一行”“第二行 abc”两条短消息被提交给了模型（各一次很短的调用）。之后所有试验都只用本地斜杠命令（`/context` 等）、按键，以及不按回车的输入。

## S1 PTY：卡住的原因和解法

| 项目 | 结论 |
|---|---|
| 《开发指南》S1 示例卡住的原因 | **ConPTY 启动时（Win10 19044 的系统版）会先向宿主输出 `ESC[6n`（查询光标位置），并且一直等回应**。示例程序从不应答，子进程停在初始化，`child.wait()` 在约 40 秒后随 conhost 放弃而返回，退出码 `0xC0000142`（`STATUS_DLL_INIT_FAILED`），此前只读到这 4 个字节。不是 `exit` 没收到，也不是 `drop(slave)` 的问题 |
| 解法 | 读线程里发现输出中的 `ESC[6n`，立刻向 PTY 写 `ESC[1;1R`，并把这 4 个字节从输出里剔除（只处理流开头 4KB 内的第一次，之后的 `ESC[6n` 是程序自己发的，原样交给主控端的 xterm.js）。不剔除的话 xterm.js 会再答一次，多出来的应答会被当成按键输入 shell。实现在 `host/pty.rs` |
| 修复后的现象 | `cmd.exe`、`powershell.exe` 写入 `exit` 后立即收到退出码 0，读线程随 master 关闭而结束（`spike-s2 s1-cmd.txt / s1-powershell.txt`） |
| 子进程退出后读线程不返回 | 按文档做：独立等待线程 `child.wait()` → 先发退出码 → 再关闭 master（`ClosePseudoConsole`）→ 读线程读到 EOF。单元测试 `echo_and_exit` / `kill_ends_all_threads` 验证 |
| 作业对象杀进程树 | `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`；shell 里启动 `ping -n 120` 后 `kill()`，进程树内无残留（`kill_takes_descendants`，用 sysinfo 查后代进程） |
| 反压 | 不读取 `output` 时 shell 输出 3000 行，读线程在容量 64 的通道上阻塞，之后读取数据完整（`backpressure_does_not_lose_data`）；流控整链路：向主控端不确认时，被控端在约 4MB 处停读（`flow_control_pauses_at_4mb_and_resumes_on_ack`，6MB 文件） |
| Ctrl+C | 写入 `0x03` 能中断 shell 里的 `ping -t`（`ctrl_c_reaches_running_program`）。**踩坑**：如果启动本进程的父进程把 Ctrl+C 设成了“忽略”（某些工具外壳会这么做），这个标志会被子进程继承，shell 里的程序收不到 Ctrl+C。`spawn_pty` 第一次调用时执行 `SetConsoleCtrlHandler(NULL, FALSE)` 恢复默认 |
| UTF-8 | cmd 用 `/K chcp 65001 >nul` 实测可用（`mode con` 显示 Code page 65001）；PowerShell 启动参数里设置 `[Console]::OutputEncoding`（乱码场景未单独验证） |
| 窗口尺寸 | 带 50ms 防抖；`mode con` 显示的行列与设置一致 |
| 自带新版 ConPTY（`conpty.dll` + `OpenConsole.exe`） | **`portable-pty` 0.9 会自动加载“可执行文件同目录”的 `conpty.dll`，不需要额外代码**（源码 `win/psuedocon.rs` 里先试 `conpty.dll`，失败才用 kernel32）。实测：把 NuGet 包 `Microsoft.Windows.Console.ConPTY` 1.24.261001001 的 x64 `conpty.dll`（109,920 字节）和 `OpenConsole.exe`（1,066,808 字节，均为 Microsoft 签名，签名有效）放在可执行文件旁边，`tasklist` 里出现 `OpenConsole.exe`，shell 正常工作。两个文件缺一不可 |
| 新版 ConPTY 的启动序列 | 以 `ESC[1t ESC[c ESC[?1004h ESC[?9001h` 开头；**不再发 `ESC[6n`**，发 DA1 查询 `ESC[c`，但不应答也不卡。主控端 xterm.js 会自己应答 DA1，应答会作为 `TermInput` 写回 PTY，由 ConPTY 的输入解析器消费 |
| 未验证 | Win11、macOS、Linux 的 PTY 行为；Unix 上 SIGHUP→3s→SIGKILL 的路径（代码已写，只做了类型检查）；Unix 登录 shell、LANG 补全 |

## S2 向 Claude Code 提交消息

测试方法：用 `spike-s2` 驱动一个 120x40 的 PTY，用 `vt100` 还原屏幕，通过输入框内容判断。`claude` 的环境变量里清掉了外层 Claude Code 继承来的 `CLAUDE*` 变量。

| 项目 | 系统 ConPTY（Win10 19044） | 自带新版 ConPTY（1.24.261001001） |
|---|---|---|
| 启动后是否出现 `ESC[?2004h` | **是**（启动序列里：`ESC[?2004h ESC[?2031h ESC[?1004h ESC[?9001l`）。本机这个版本用经典渲染器，没有备用屏幕（无 `?1049h`），也没有鼠标模式 | 同左 |
| 单行斜杠命令 `/context`：bracketed paste + 回车（回车前等 0 / 30 / 80 / 150 / 300 ms） | 5 个等待值**全部成功**（屏幕出现 “Context Usage”） | 同左（抽测） |
| 同一命令不包粘贴、直接写入，再等 0 / 30 / 80 / 150 / 300 ms 回车 | **全部成功** | 同左（抽测） |
| **多行文本，粘贴内部换行用 CR** | **失败：CR 被当成回车，第一行被提交**。说明系统 ConPTY 并没有把 `ESC[200~…ESC[201~` 当作粘贴交给 Claude Code（长文本粘贴也不折叠成 `[Pasted text]`，等同于逐字输入） | **成功**：识别为粘贴，两行都留在输入框里，没有提交 |
| 多行文本，粘贴内部换行用 **LF** | 成功：输入框里是多行，未提交 | 成功 |
| 退路：逐行输入 `\` + CR 作为续行 | 成功（输入框里得到两行，反斜杠被吃掉） | 同左（未单测，逻辑相同） |
| 5000 个汉字，一次粘贴（按 2KB 分块、块间 5ms） | 进入输入框，末尾内容完整出现（未逐字比对） | 折叠成 `[Pasted text #1]` |
| 20 行，含反引号、双引号、emoji、中文 | 逐行显示在输入框里，最后几行完整 | 折叠成 `[Pasted text #2 +19 lines]` |
| 完整提交（多行消息 + 回车） | **未验证**：需要真的向模型提问。用 `press_enter=false` 验证了“进入输入框”这一半；回车提交用 `/context`、`/exit` 验证 | 同左 |

**对默认规则的影响**（`host/adapter.rs` 的内置规则）：

- Claude Code 规则：`paste: bracketed`，**`newline_in_paste` 改为 `"\n"`**（《实现方案》5.5.4 的示例是 `"\r"`，在系统 ConPTY 上会提前提交，LF 在两种 ConPTY 上都对），`submit_delay_ms: 80`，`fallback_newline: "\\\r"`（反斜杠加回车，实测可用）。
- 等待时间：单行命令 0ms 也成功，保留 80ms 作为保守值。长文本（5000 字）的合适等待未单测——粘贴内容本身按 2KB 分块写入，回车在最后一块之后等待 `submit_delay_ms`。
- 通用规则：沿用 `\r`（只在远端开启 `?2004` 时才用 bracketed）。

## S3 图片路径

| 项目 | 结论 |
|---|---|
| 把图片**路径单独**作为一次 bracketed paste（裸路径 / 双引号 + 空格 / 双引号 + 中文） | **新版 ConPTY：输入框里立刻变成 `[Image #n]` 标记**，三种写法都识别。系统 ConPTY：保持为文字路径（没有粘贴识别） |
| 路径夹在一大段文字里的同一次粘贴（`what is in "路径" thanks`） | 不识别，保持文字路径（模型仍可用读文件工具读取，功能不受影响） |
| 文字、路径、文字分成三次粘贴 | 识别，得到 `what is in [Image #1] thanks`，但**路径粘贴之后必须等一会儿再写后面的内容**：间隔 0ms 时 `[Image #n]` 标记是异步追加的，会跑到末尾（`what is in  and  thanks[Image #1] [Image #2]`）；间隔 100ms 顺序正确 |
| 两个路径在同一次粘贴里（空格分隔） | 得到两个 `[Image #n]` |
| 引号规则 | 含空格用双引号（Windows）；Unix 用单引号（**未在 Unix 上验证**）。无空格的路径不加引号 |
| 模型是否真的“看到”图片 | **未验证**（需要提交给模型） |

**对输入适配器的影响**：Claude Code 规则新增 `attach_separate: true`、`attach_gap_ms: 150`：每个附件路径单独一次粘贴，其后等 150ms；相邻附件合并成一次粘贴；没有占位符的附件追加到末尾。通用规则仍把路径内联。端到端结果（`host_claude_e2e`）：新版 ConPTY 上 `"这张图里有什么？\u{FFFC} 谢谢"` 变成 `这张图里有什么？[Image #1] 谢谢`；系统 ConPTY 上是带引号的完整路径文字。

## S5 命令、按键、hooks（V12–V20）

| 编号 | 结论 | 说明 |
|---|---|---|
| V12 粘贴方式写命令 | **可行** | `/context`、`/exit` 用 bracketed paste 或直接写入，回车前等待 0–300ms 均被当作命令执行。**没有测 `/model sonnet`**（会把默认模型写进用户设置，`/model` 的带参数形式也未测）；带参数命令用 `type` 步骤的退路在执行器里实现了，但本机无需启用 |
| V13 按键 | **可行（系统 ConPTY 与新版 ConPTY 一致）** | `ESC[Z`（Shift+Tab）循环 auto → manual → accept edits → plan → auto；**Alt+M（`ESC m`）无反应**，所以 Windows 上不需要退路，默认目录里的 `windows_no_vt` 覆盖保留但默认关闭；`ESC t`（Alt+T）被识别（本账号 Sonnet 5.5 提示“Thinking can't be turned off”）；`0x0f`（Ctrl+O）进入详细 transcript；`ESC p`（Alt+P）打开模型选择菜单（菜单底部写着“Enter to set as default · s to use this session only · Esc to cancel”）；`ESC`（Esc）关闭菜单。**Esc 打断正在输出的 Claude Code：未验证**（需要模型在输出） |
| V14 插件加载与叠加 | **可行** | `--plugin-dir` 指向只含 `.claude-plugin/plugin.json`（name/version/description）和 `hooks/hooks.json` 的目录即可加载，hooks 触发。在项目 `.claude/settings.json` 里另配 `SessionStart` hook，**两个 hook 都触发（叠加）** |
| V15 `--settings` 与状态栏 | **覆盖用户的状态栏；链式调用可行** | 项目 settings 里配 `statusLine` 时，传 `--settings` 后用户的状态栏被我们的命令替换（显示 `RTerm`）；设置 `RTERM_USER_STATUSLINE` 后由 `hook --statusline` 调用原命令并原样输出，状态栏恢复为用户原来的内容。状态栏命令在会话开始后约 0.6 秒被调用；`/context` 之后没有立刻再调用 |
| V16 事件字段 | **部分验证** | 已拿到：`SessionStart`（`cwd, hook_event_name, model("claude-sonnet-5-5"), scratchpad_dir, session_id, source, transcript_path`）、`SessionEnd`（`cwd, hook_event_name, prompt_id, reason("prompt_input_exit"), session_id, transcript_path`）、状态栏 JSON（`model.{id,display_name}, context_window.{context_window_size,used_percentage(启动时为 null),remaining_percentage,total_input_tokens,…}, cost.total_cost_usd, effort.level, fast_mode(bool), thinking.enabled, version, workspace.{current_dir,project_dir,added_dirs}, output_style.name, session_id, cwd, transcript_path`；**没有 `session_name` 字段**，`permission_mode` 也没有，与文档一致）。**未验证**（需要模型回合）：`UserPromptSubmit`（`/context` 这类内置斜杠命令**不会**触发它）、`PermissionRequest`（工具名和参数字段）、`PostToolUse`、`Stop`、`StopFailure`、`Notification`、`PostModelSwitch`（新模型字段）、`CwdChanged`。解析代码对这些做了容错（见 `host/status.rs`），字段名以文档为准 |
| V17 hook 耗时 | **可行** | 用被控端自己的 `hook_main` 编成的 `hookprobe.exe`（debug 构建，未优化）：无环境变量 6ms；有环境变量但主进程不在 7ms；连上真实服务端发送并退出 20 次，平均 9ms、最大 32ms（含 PowerShell 启动开销）。远低于 300ms。Win10 之外未测 |
| V18 权限提示的 Enter/Esc | **未验证** | 需要触发真实的权限请求（模型回合）。权限按钮的 `notice_id` 校验已实现并有单测，但按钮是否发对键需要在有模型额度的环境里实测；不通过时的退路是权限卡片只展示不做按钮 |
| V19 命令的 shell 与路径 | **可行** | Claude Code 在本机用 **Git Bash（`$0` = `/usr/bin/bash`）** 执行 hook 和状态栏命令，不是 cmd。因此 hooks.json 里的命令用 `"<正斜杠路径>" hook`；链式调用用户原状态栏命令时，`hook --statusline` 也优先用 Git Bash（`CLAUDE_CODE_GIT_BASH_PATH` 或 `C:/Program Files/Git/bin/bash.exe`），找不到才退到 cmd。实测路径含空格、含中文（hook 程序、插件目录、`--settings` 文件）都能工作；PowerShell（单引号）和 cmd（双引号）两种方式拼出的启动命令（`--model 'sonnet' --permission-mode plan --effort high --name '我的 任务' --plugin-dir '…空格…' --settings '…'`）实测启动后是计划模式、强度 high，hooks 与状态栏都触发。bash/zsh 的单引号在 Linux/macOS 上**未验证** |
| V20 工作中发斜杠命令 | **未验证** | 需要模型在工作状态 |

## 汇总

| 事项 | 结论 |
|---|---|
| 阻塞项 | 无。S1 的“卡住”已查明并修复 |
| 需要产品层面决定的 | 1) 在 Win10 上是否随包带新版 ConPTY：不带则粘贴不被 Claude Code 识别为粘贴，图片路径只能是文字路径（功能可用，体验降级）；带则只需放两个文件，无需改代码。2) Windows 上是否必须安装 Git Bash：用户的原状态栏命令按 bash 写，链式调用依赖 bash，找不到时退到 cmd |
| 与文档不一致的点 | 见各表中的“实测”说明：`newline_in_paste` 由 `\r` 改为 `\n`；hook 命令路径用正斜杠；Claude Code 在 Windows 上用 Git Bash 执行 hook；状态栏没有 `session_name`；`/context` 等内置斜杠命令不触发 `UserPromptSubmit` |
