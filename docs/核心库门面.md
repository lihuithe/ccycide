# 核心库门面（rterm-core::core）

界面层（Tauri）和命令行都只通过 `rterm_core::core::Core` 使用核心库。代码在 `crates/rterm-core/src/core.rs`，配套模块：`settings.rs`（设置）、`dto.rs`（给前端的结构和事件）、`error.rs`（错误码）、`logging.rs`（日志）。

## 启动

```rust
let mut o = CoreOptions::new(CoreKind::Desktop, env!("CARGO_PKG_VERSION"));
o.rterm_cli = Some(path_to_rterm_cli);          // 状态回传 hook 用；None 时桌面版找同目录的 rterm-cli
let (core, mut events) = Core::start(o).await?; // events: mpsc::Receiver<CoreEvent>，有界，必须持续取走
```

| `CoreOptions` 字段 | 说明 |
|---|---|
| `api_url` | 服务端地址（不含 `/v1`）。优先级：此项 > 环境变量 `RTERM_API_URL` > 配置文件 > 内置默认（编译时 `RTERM_DEFAULT_API_URL`，缺省 `http://127.0.0.1:8080`） |
| `data_dir` | 数据目录。None = 平台标准目录，环境变量 `RTERM_DATA_DIR` 可整体覆盖 |
| `kind` | `Desktop` / `Cli`，注册时上报 |
| `rterm_cli` | `rterm-cli` 可执行文件绝对路径 |
| `proxy` | 本次运行的手动代理，覆盖配置（空串 = 不用代理） |
| `secrets` | 机密存储。None = 系统钥匙串，不可用退回 0600 文件；`RTERM_NO_KEYRING=1` 强制文件（测试用） |
| `probe_claude` | 启动时 `claude --version` 探测，默认 true |
| `controller_timing` | 主控端时间参数（测试缩短退避）。默认 Ping 间隔 5 秒（保活 + 延迟上报） |
| `config_pubkeys` | 受信的配置签名公钥（嵌入/测试用）。None = 内置公钥；`RTERM_CONFIG_PUBKEY` 可覆盖（debug 构建，或同时设 `RTERM_ALLOW_CONFIG_PUBKEY_OVERRIDE=1`）。`/v1/config` 里 `adapters` / `claude_catalog` 的 `config_sig` 验签失败或缺失时整份忽略，只用内置规则（见 `config_sig.rs`、实现方案 6.7） |
| `init_logging` / `log_to_stderr` | 为 true 时由 Core 初始化日志（`logging::init`，数据目录下 `logs/`，按天滚动保留 7 天）。默认 false：调用方已自己调用过 `logging::init` 的保持兼容 |

**强制 TLS**：API 地址、信令地址（含服务端下发的 `signal_url`）、中继地址必须是 `https://` / `wss://`；只有回环地址（`127.0.0.1` / `localhost` / `::1`）在开发开关打开时允许 `http://` / `ws://`（debug 构建默认打开；发布构建需环境变量 `RTERM_ALLOW_INSECURE_LOOPBACK=1`）。发布构建的 `RTERM_DEFAULT_API_URL` 必须指向 https 地址，否则默认地址会被拒绝。下发的明文 `signal_url` 被忽略并由 `api_url` 推导。

**机密存储读失败不重新生成身份**：钥匙串暂时读不出设备私钥（`SecretError::Unavailable`）时，`Core` 按"稍后重试"处理（`lastError` 有说明），不会生成新的设备私钥；私钥长度异常同样报错而不是静默替换。

**服务端不可达**：`start` 不会因此失败。返回正常的 `Core`，`local_info().registered == false`、`lastError` 是原因（如“无法连接服务器 http://…”），后台按 2、4、8…30 秒退避自动重试，`Core::retry_register()` / `network_changed()` 立即重试。成功后发 `LocalInfoChanged`。注册前调用连接类接口返回 `NOT_REGISTERED`；设置、已记住设备等本地接口照常可用。`start` 只在本地问题时返回 Err（数据目录不可写、配置版本过新）。

**连接确认与主控取消**：主控端 `connect` 不再有超时，先收到 `SessionState(AwaitingApproval)`（带会话 id），对方用户确认后才继续握手；断线重连的尝试不受 `cancel_connect` 管，用 `disconnect`。

**服务端重置**：信令认证返回 `UNKNOWN_DEVICE`（服务端数据被清空，开发用的内存库重启就会）时，核心自动清掉旧登记、用同一把密钥重新注册并重建被控/主控部分，发 `Notice{code:"RE_REGISTERED"}`；设备码会变，固定密码与设备码绑定，随之清除，进行中的会话和终端被结束。

## API 清单

所有方法都是 `async`（除标注“同步”）且返回 `CoreResult<T>`（`CoreError { code, message, data? }`，可直接序列化为前端的 `CommandError`）。

| 分类 | 方法 | 说明 |
|---|---|---|
| 本机 | `local_info()` 同步 | 前端 `LocalInfo`（另有 `registered`、`lastError`、`lockedRemainingSecs`、`activeSessions`） |
| | `refresh_temp_password()` | Argon2 在 `spawn_blocking` 里算，返回新密码 |
| | `set_fixed_password(Option<&str>)` | None/空串 = 清除；弱密码 `WEAK_PASSWORD`（至少 10 位、至少 3 类字符、弱口令检测，见实现方案 5.5.6）；派生值存机密存储 `fixed-pw-key`；Argon2 派生失败时返回错误且不保存（`crypto::derive_pw_key` 现在返回 `Result`，不再有全零密钥） |
| | `list_incoming()` 同步 | 来访会话（含等待确认的） |
| | `accept_incoming(sid)` / `reject_incoming(sid)` 同步 | 等待确认的来访。**不超时**，一直挂着直到用户处理、主控方取消、或被控端设置变化（`enabled` 关闭 -> 全部拒绝；`requireConfirm` 关闭 -> 全部放行）。可同时挂多个 |
| | `disconnect_incoming(sid)` / `disconnect_all_incoming()` 同步 | 踢掉来访会话 |
| 设置 | `get_settings()` 同步 / `set_settings(Settings)` | 校验、持久化、热生效，发 `SettingsChanged`，返回保存后的设置 |
| | `config_get(path)` / `config_set(path, value)` | 命令行用，点分路径，`host.requireConfirm` 或 `host.require_confirm` 均可 |
| 已记住设备 | `list_known_hosts()` / `remove_known_host(code)` / `set_known_host_alias(code, alias)` | 同步，TOFU 记录 |
| 主控 | `connect(code, password)` → `SessionId` | 设备码可带空格/短横线 |
| | `connect_with(ConnectParams{ device_code, password, accept_key_change })` | 公钥变化后的确认重连 |
| | `cancel_connect(sid)` 同步 | 取消还没连上（含“等待对方确认”）的连接，`sid` 取自 `SessionState(Connecting/AwaitingApproval)` 事件；对应的 `connect` 返回 `CANCELLED` |
| | `disconnect(sid)`、`sessions()` 同步、`host_snapshot(sid)` 同步 | |
| | `open_term(sid, TermOpenOptions)` → `TermId`；`open_term_ui(sid, OpenTermParams)` → `{termId,title,shell}` | 后者参数形状对应前端 `TermOpenParams` |
| | `list_terms(sid)` → `Vec<TermInfoDto>` | 含 `attachedByOther` |
| | `attach_term(sid, term, TermSize)` | 被其他设备占用返回 `TERM_BUSY`；输出从本端已收到的偏移之后回放 |
| | `attach_term_from(sid, term, TermSize, Option<u64>)` | 同上，另指定前端已渲染偏移 `from_seq`（前端 `lastSeq`）：小于控制器已交付偏移时回退并重新交付 `[from_seq, …)`；None 等价于 `attach_term` |
| | `term_input` / `term_submit` / `term_resize` / `close_term` | 会话不在 Ready 返回 `NOT_READY` |
| | `term_ack(sid, term, consumed)` 同步 | 界面渲染后调用，节流由调用方做（每 256KB 或 100ms） |
| | `upload(sid, UploadSource)` → `FileId`；`upload_path(sid, &Path)`；`upload_bytes(sid, name, mime, data)` | 后两者返回 `{fileId,name,size}`；目录 `IS_DIRECTORY` |
| | `cancel_upload(sid, file)` 同步 | |
| | `term_action(sid, term, action_id, args)` → `{passthrough, returnKeys}` | 内部等待被控端的 `TermActionResult`（20 秒）；失败的错误码是被控端给的 `UNSUPPORTED/BAD_REQUEST/APP_NOT_RUNNING/BUSY/TERM_NOT_FOUND` |
| | `command_list_req(sid, term)` | 结果走 `CommandList` 事件 |
| 生命周期 | `network_changed()` 同步 | 睡眠唤醒 / 网络切换时调用：信令立即重连、主控会话立即重试、未注册则立即重试注册 |
| | `retry_register()` 同步、`shutdown()` | `shutdown` 断开全部会话、关闭终端、停后台任务 |
| 转换 | `ui_event(&CoreEvent) -> Option<UiEvent>` 同步 | 转成前端契约的 JSON 事件，见下 |
| 其他 | `server_config()`、`paths()`、`kind()`、`api_url()` | |

离线工具：`LocalStore::open(data_dir, secrets)` 提供不启动 `Core` 的配置读写和 `set_fixed_password_offline`（命令行在后台进程没运行时用）。

## 事件

`mpsc::Receiver<CoreEvent>`（`events.rs`）。`dto::UiEvent` 与前端 `CoreEvent` 一一对应（`#[serde(tag="type", camelCase)]`），Tauri 层 `if let Some(e) = core.ui_event(&ev) { app.emit("core-event", e) }` 即可；`TermOutput` 返回 None，走输出通道（帧格式见 `types.ts`）。

| CoreEvent | 前端事件 | 备注 |
|---|---|---|
| `SignalState` | `signalState` | |
| `IncomingSession` / `IncomingClosed` | `incomingSession` / `incomingClosed` | 同一 session 可能出现两次：先 `pendingConfirm:true`，握手成功后 `false`（按 sessionId 更新）。不需要确认时只在握手成功后出现一次 |
| `SessionState` | `sessionState` | `connecting` / `awaitingApproval`（已发出请求，等对方用户确认，可 `cancel_connect`）/ `ready` / `reconnecting`。`Closed` 不转发，由下一条带原因码的 `SessionClosed` 承担 |
| `ReconnectInfo{attempt,retry_in_ms}` | `sessionState{state:'reconnecting', attempt, retryInMs}` | 每次自动重连退避开始时一条（紧跟在 `Reconnecting` 之后） |
| `SessionClosed{code}` | `sessionState{state:'closed', reasonCode}` | `PASSWORD_WRONG`（要求重输密码）、`USER`、`CANCELLED`、`PEER_KEY_CHANGED`、`HOST_BYE`、`REFUSED` |
| `Latency` | `latency` | 每 5 秒 |
| `HostInfo` | `hostInfo` | `features` 取自 HelloAck |
| `TermState` / `TermExit` / `Upload*` / `ActionCatalog` / `AppState` / `AppNotice` / `CommandList` | 同名 | 终端级错误（`TERM_BUSY` 等）经 `AppNotice{kind:'error', title:码}` 到达 |
| `ActionResult` | （无） | 由 `term_action` 的返回值承载 |
| `SettingsChanged` / `LocalInfoChanged` | 同名 | 临时密码刷新、锁定、注册状态变化时发 |
| `Notice{level,code,text}` | `notice`（契约外新增） | `SERVER_NOTICE`、`KICK`、`HOST_LOCKED`、`RE_REGISTERED`、`INCOMING_CANCELLED`（对方在确认前取消了请求，随后是 `IncomingClosed`）、信令认证错误 |
| `UpgradeRequired{minVersion,currentVersion,latestVersion}` | `upgradeRequired`（契约外新增） | 当前版本低于 `/config` 的 `min_app_version`，或信令返回 `VERSION`；应阻止使用并引导升级 |

注意：事件通道有界。处理事件的任务里不要 `await` 会话命令（`term_ack` 是同步的，可以调）。

## 设置项（`settings.rs`，camelCase，与前端 `Settings` 一致，另有扩展字段）

| 路径 | 默认 | 生效 |

| `host.requireConfirm` | false | 热 |
| `host.tempPasswordPolicy` | `on_start` | 热。`on_start` / `after_session` / `manual` |
| `host.fileReceive` | true | 热 |
| `host.maxFileSize` | 200MB | 热 |
| `host.maxTerminals` | 16 | 热 |
| `host.detachedTermTtlHours` | 24 | 热。0 = 永不 |
| `host.isolateTerminals` | true | 热，持久化。对之后的 `list_terms` / `attach_term` 立即生效，已附着的不踢 |
| `host.notifyOnConnect` / `preventSleepWhenConnected` | true / false | 界面层使用 |

| `host.defaultShell` | null | 重启生效 |
| `controller.fontSize` `theme` `notifyOnDone` `notifyOnPermission` `scrollback` `fontFamily` | 14 / auto / true / true / 10000 / null | 界面层使用 |

| `app.autostart` `closeToTray` `updateChannel` `crashReport` `safetyNoticeAcked` | false / true / stable / false / false | 界面层使用 |

`set_settings` 收到的是完整对象（前端往返时必须带回它不认识的扩展字段）；缺失字段取默认值。`fixedPasswordSet` 不在设置里，见 `local_info()`。

## 错误码

与前端 `ErrorCodes` 一致：连接类 `UNAVAILABLE REJECTED RATE_LIMITED LOCKED VERSION BANNED NO_RELAY PASSWORD_WRONG NETWORK`；会话/终端 `NOT_READY TERM_BUSY TERM_LIMIT TERM_NOT_FOUND SPAWN_FAILED`（被控端原样透传）；文件 `IS_DIRECTORY FILE_TOO_LARGE FILE_DISABLED`；动作 `UNSUPPORTED BAD_REQUEST APP_NOT_RUNNING BUSY`。新增：`CANCELLED`、`PEER_KEY_CHANGED`（`data:{known,actual}` 是两个公钥的指纹；用户确认后用 `connect_with(accept_key_change:true)` 重连）、`NOT_REGISTERED`、`WEAK_PASSWORD`、`NO_SUCH_SESSION`、`TIMEOUT`、`CLOSED`。

## Tauri 命令 → 门面

`local_info` `refresh_temp_password` `set_fixed_password` `accept_incoming` `reject_incoming` `disconnect_incoming` `disconnect_all_incoming` `list_known_hosts` `remove_known_host` `get_settings` `set_settings` `connect`（建议多接一个可选参数 `acceptKeyChange` 调 `connect_with`；它会一直等到对方确认，期间事件里有 `awaitingApproval` 和会话 id，新命令 `cancel_connect(sessionId)` 取消）`disconnect` `open_term`（用 `open_term_ui`，输出通道在 Tauri 层按 `(sessionId, termId)` 路由 `TermOutput` 事件）`list_terms` `attach_term`（用 `attach_term_from(…, Some(lastSeq))`）`term_input` `term_submit` `term_resize` `term_ack` `close_term` `upload_path` `upload_bytes` `cancel_upload` `term_action` `command_list_req` 都是对同名门面方法的一行封装；`read_clipboard_files`、对话框、通知、自启、更新属于 Tauri 层。托盘“暂停被控”= `get_settings` 改 `host.enabled` 后 `set_settings`；“断开全部”= `disconnect_all_incoming`；睡眠唤醒 / 网络变化 = `network_changed`。

## 被控端对来访连接的处理

`connect.incoming`（不再带中继地址）→ `Guard::admit`（已建立 + 握手中的会话合计不超过 `max_sessions`，否则 `busy`；放行后、`connect.accept` 之前再用 `Guard::begin_handshake` 预留"握手中"名额，握手结束归还）：拒绝则 `connect.reject`（原因 `disabled/locked/busy`）；需确认则同步登记并发 `IncomingSession{pendingConfirm:true}`，一直等 `accept_incoming` / `reject_incoming`（也可能收到 `IncomingCancelled`：主控方取消，发 `Notice(INCOMING_CANCELLED)` + `IncomingClosed`）；同一台主控设备在上一个会话结束或获准后 2 分钟内重连不再重复确认（`RECONNECT_GRACE`，避免网络闪断后让被控端用户再点一次）；放行 → `connect.accept` 并等 `connect.go{relay_url,ticket}` → 握手 → 成功：`report_auth_success` + `session.report(auth_ok)` → `HostSession::run_with_kick` → 结束：`report_session_end` + `session.report(closed)`。握手 `BadPassword`：`report_auth_failure` + `session.report(auth_failed)`，触发锁定再报 `host_locked`。信令 `accept` 只反映 `host.enabled`，锁定期间保持在线，由服务端回 `LOCKED`。握手传给 `HostSession` 的 `Link.peer.device_code` 是信令下发、握手里用其公钥验签通过的主控设备码（终端隔离按它识别“同一台主控”）。

## 本机 IPC 约定

1. **命令行 ↔ 后台进程**（`crates/rterm-cli/src/ipc.rs`）：`interprocess` 本地套接字。Unix `<配置目录>/rterm.sock`（0600），Windows 命名管道 `rterm-ipc-<配置目录哈希>`。每个连接一问一答：客户端发一行 JSON（`{"cmd":"status"}`、`passwd_random`、`passwd_set`、`config_get`、`config_set`、`accept`、`reject`、`disconnect`、`stop`、`ping`、`passwd_show`），服务端回一行 `{"ok":bool,"error"?,"error_code"?,"data"}` 后关闭，单行上限 64KB。同一数据目录只允许一个后台进程。
2. **Claude Code 状态回传**（`host/status.rs`）：hook 命令 `rterm-cli hook [--statusline]` 读环境变量 `RTERM_TERM_ID` / `RTERM_HOOK_ENDPOINT`，往 `BridgeServer`（Windows 命名管道 / Unix `bridge-<pid>-<随机>.sock`）发一行 `{"term_id","token","kind","payload"}`。`token` 是该终端创建时生成的 128 位随机令牌（环境变量 `RTERM_HOOK_TOKEN`，32 个十六进制字符），`BridgeServer` 用常数时间比较，没带、不对、终端已关闭的事件丢弃（每个终端只记一次日志）；Windows 管道 DACL 只给创建者和 SYSTEM 并拒绝远程客户端，Unix 套接字 0600。`AppNotice` 新增 `truncated`：权限卡片的工具摘要超过 4000 字符时为 true，被控端拒绝 `permission.allow`（`BAD_REQUEST`），界面应只提供“拒绝”；同步实现、不启动 tokio、退出码恒为 0，实测约 70ms（含进程启动）。

## 目录与日志

配置 `config.json`、机密文件 `secrets/`（钥匙串不可用时）、`inbox/`、`logs/`、`claude-plugin/` 都在数据目录下（Windows `%APPDATA%\RTerm\`，Linux `~/.config/rterm/` + `~/.local/share/rterm/`）。日志 `logging::init(logs_dir, to_stderr)`：按天滚动 `rterm.<日期>.log`，保留 7 天；不记录终端内容、密码、文件内容，设备码只记后 4 位（`logging::mask_code`）。

## 命令行子命令

`host [--quiet] [--verbose]`、`status [--json]`、`id [--raw]`、`passwd [--random | --set [--stdin] | --clear]`、`config get|set`、`install [--no-start] [--print]` / `uninstall`（Linux systemd user unit、macOS launchd agent，Windows 不支持）、`logs [-n N] [-f]`、`accept` / `reject` / `disconnect [--all]` / `stop`、隐藏的 `hook [--statusline]`。全局 `--data-dir`、`--api-url`。`status` / `passwd` / `config` 等在后台进程运行时走 IPC（设置热生效），没运行时直接读写本地配置和机密存储（下次启动生效）。
